# QvQMemes

**Система стикеров для агента [QvQChat](https://github.com/wsu2059q/ErisPulse-QvQChat): сама подхватывает мемы из групповых чатов, сама расставляет теги визуальной моделью, а когда отправить стикер и какой именно — решает ИИ.**

Большинство «мем-плагинов» устроены как однорукий бандит: пришло сообщение — бросается кость, из папки выпадает случайная картинка, и результат не имеет никакого отношения к тому, о чём шла речь. Этот модуль занимает противоположную позицию. Стикер здесь — часть самовыражения агента, и единственный путь из библиотеки наружу — инструмент `send_sticker`, который экосистемный мост QvQChat регистрирует как обычный ИИ-инструмент. Отправлять ли стикер сейчас — подхватить шутку, добавить эмоции, ответить колкостью — целиком на усмотрении модели, и единственная подсказка ей — описание инструмента («подходит для лёгких, шутливых и эмоциональных моментов; в серьёзных задачах используйте с осторожностью»). Нигде в этой цепочке нет ни таймера, ни игральной кости — в этом принципиальное отличие от плагинов «случайного мем-баттла», и оно сделано намеренно.

«Какой именно» решается так же. Модель формулирует смысловой запрос («самодовольный кот», «поблагодарить, но вежливо»), а модуль детерминированно сверяет его с описаниями и тегами каждого стикера: точное совпадение тега — 4 балла, вхождение в тег — 2, попадание в описание — 3, всё суммируется по словам, — и отправляется стикер с наивысшим счётом. Сбор тоже не требует рук: картинки, пролетающие в групповых чатах, подхватываются через событие `qvq.observe` в QvQChat, визуальная модель просматривает каждую и пишет однострочное описание содержания и настроения плюс три-шесть тегов сцен использования. Никто не размечает ничего вручную. Единственная корректировка порядка, которую модуль себе позволяет, — понижение по свежести: стикеры, отправленные в окне `recency_hours`, получают при поиске половинный счёт, чтобы агент не долбил одну и ту же картинку всю неделю. Это детерминированное планирование, а не вероятность: недавние понижаются, при переполнении библиотеки выталкиваются самые давно неиспользуемые — и больше ничто порядок не меняет.

## Установка

Требуется [QvQChat](https://github.com/wsu2059q/ErisPulse-QvQChat) 4.0.4 или новее — событие `qvq.observe` и страница настроек плагинов, с которыми работает этот модуль, появились именно в этой версии — поверх ErisPulse 2.8.0+.

```bash
epsdk install ErisPulse-QvQMemes
# или
pip install ErisPulse-QvQMemes
```

## Начало работы

Включать ничего не нужно. Как только модуль загружается, экосистемный мост автоматически превращает его сервисы в ИИ-инструменты: агент получает `send_sticker` вместе с `sticker_search`, `sticker_stats` и `sticker_add`, а при удалении модуля так же тихо их теряет. Настройки появляются в Dashboard QvQChat, в разделе плагинов на странице настроек.

Библиотека стикеров по умолчанию лежит в `data/QvQMemes/stickers`. Собранные из чатов картинки скачиваются туда под именем из первых 16 шестнадцатеричных символов хэша содержимого; при каждом старте модуль сканирует каталог и забирает в библиотеку и те картинки, которые вы положили туда сами. Просто закинуть в неё папку с мемами — вполне законный способ заложить фонд.

## Как это устроено

Сбор работает по обходному пути и никогда не блокирует основной конвейер чата. Когда QvQChat рассылает `qvq.observe` (каждое групповое сообщение, которое он видит, до трёх картинок на сообщение), модуль быстро проверяет полезную нагрузку и передаёт работу фоновой задаче. Та сначала отбрасывает дубликаты по URL и по хэшу содержимого, затем проверяет дневной лимит на чат, потом последовательно скачивает уцелевшее на диск — при неудачной загрузке ссылка URL сохраняется, и стикер всё равно можно отправить, — и ставит его в очередь на расстановку тегов. Тегирование идёт через `describe_image` в QvQChat; если визуальной модели нет или вызов не удался, запись просто помечается как «без тегов» и остаётся доступной поиску по описанию. Ни одно звено этой цепочки не фатально. Все записи хранятся в key-value хранилище фреймворка в виде `{id, path, url, desc, tags, source, uses, last_used, added}`.

Отправка идёт через SendDSL платформенного адаптера, поэтому на любой поддерживаемой фреймворком платформе ведёт себя одинаково:

```python
# То, что экосистемный мост реально исполняет, когда модель вызывает инструмент send_sticker:
await sdk.module.call("QvQMemes", "send_sticker",
                      query="самодовольный кот, злорадство",
                      platform="qqbot",
                      target_id="123456",
                      target_type="group")
# -> "Sent: a smug white cat rolling its eyes | smug teasing comeback"
```

Если совпадений нет, в ответе так и сказано — и приводятся самые частые теги библиотеки, так что модель может переформулировать запрос и попробовать снова, а не молча провалиться.

## Настройки

Параметры объявлены в ConfigClass модуля и автоматически отрисовываются формой на странице настроек QvQChat; рабочие значения подтягиваются при загрузке через `QvQChat.plugin_config`, а при сбое модуль молча остаётся на значениях по умолчанию.

| Ключ | По умолчанию | Описание |
|------|---------|-------------|
| `library_dir` | `data/QvQMemes/stickers` | Каталог библиотеки: загрузки попадают сюда, существующие картинки забираются сканированием при старте |
| `max_library` | `500` | Вместимость библиотеки; при превышении выталкиваются самые давно неиспользуемые стикеры (ни разу не использованные считаются по времени добавления) |
| `recency_hours` | `72` | Окно свежести в часах; отправленные в нём стикеры получают при поиске половинный счёт |
| `send_method` | `Image` | Метод SendDSL для отправки (URL картинки или локальный путь) |
| `auto_collect` | `True` | Собирать картинки из полезной нагрузки `qvq.observe` (до 3 на сообщение) |
| `collect_per_chat_daily` | `20` | Дневной лимит автосбора на чат; 0 и меньше — без лимита |
| `tag_via_vision` | `True` | Расставлять теги визуальной моделью QvQChat после сбора; при недоступности запись помечается как «без тегов» |

## Сервисы

Все пять сервисов перечислены в белом списке `get_meta().services`. Они возвращают только str или dict и никогда не бросают исключений — любая внутренняя ошибка превращается в читаемый текст или поле `error`, так что модель всегда получает ответ, с которым можно работать дальше.

| Сервис | Сигнатура | Описание |
|---------|-----------|-------------|
| `send_sticker` | `(query: str, platform: str, target_id: str, target_type: str = "group") -> str` | Выбирает лучшее совпадение по смысловому запросу и отправляет; возвращает "Sent: \<desc\>", подсказку по тегам при отсутствии совпадений или текст ошибки |
| `sticker_search` | `(query: str, top_n: int = 5) -> dict` | Поиск без отправки: `{query, count, results: [{id, desc, tags, score, url, path, uses}], tag_hints}` |
| `sticker_stats` | `() -> dict` | Статистика библиотеки: `{total, max_library, untagged, added_today, tag_distribution, top_used}` |
| `sticker_add` | `(url: str = '', path: str = '', desc: str = '', tags: str = '') -> str` | Добавить стикер вручную по URL или локальному пути; опущенные desc/tags уходят в визуальное тегирование |
| `qvq_settings` | `() -> dict` | Маркер принадлежности `{"title": ...}`; только модули, объявляющие этот сервис, попадают в раздел плагинов на странице настроек QvQChat |
